## 1. 目标、职责与当前状态

1. 稀疏页审计时，可疑页仍对应正确原书物理页。
2. 有效缓存命中后，复用已有逐页结果为当前章节生成报告与已有审计字段，不再返回旧章节集合，不重做 OCR。

报告生成、缓存和目录写回均由 core 拥有；消费者消费报告，不猜配页号或补造上游结果。三个产品修正已经分别提交为 1740fafb31ca16701805693dd4669876386f2c54、38b853f1c086cb33ed2195b5a078b3cbb0495825、fd4104986b1c76050e7bc823ecff67fe4542ea4a。此次只补齐目标仓库计划，不重新实施这些修正。

## 2. 方案和事实依据

### 2.1 稀疏页号配对

下游 P6 §3.1 的 core 方案原文：
先由 `pdf-processing-core` 负责人修正 `lib/pdfx/texlayer_audit.py` 的小节聚合：从同一个 `(原书页号, 该页结果)` 对集合计算 `audited`、`suspect_pages`、比例和修复预估，不能分别过滤后再按位置拼接。只修复页号与结果的对应，保留现有审计目标、阈值、返回字段和原生 OCR 行为。完整修复路径必须锁定包含该修正的提交；本仓不得自行改写错误报告或根据另一个数组猜回页号。未来修正提交属于明确的实施依赖，不是假定当前版本已正确。

实际旧实现先过滤缺失结果，再与未过滤的物理页列表 zip，因此 40 缺失、41 可疑、42 可信时会误标 40。修改点为 lib/pdfx/texlayer_audit.py 的章节聚合；统一保存页号与结果对，计数、比例、可疑页和修复预估均从同一集合取得。替代方向是在消费者猜回页号，会重复核心规则且不能可靠恢复归属，故不采用。阈值、CLI、字段类别及原生 OCR 行为不变。已交付的 test/test_texlayer_audit.py 只落实原 L01，不增加矩阵。

### 2.2 缓存投射与共有写回

以下提取 P6 §3.1 中的 core 方案（“本仓”在引文中指 pdf-book-pipeline）：
该页号修正现已在 `1740fafb31ca16701805693dd4669876386f2c54` 完成并通过 L01。P5 在同一内核文件补齐 `sampled` 缓存返回路径：缓存有效性仍采用原有 PDF 指纹、DPI 和模式条件；命中后复用 `done_pages`，按本次 `ext_dir` 中的当前小节调用已有 `map_sections` 和 `_aggregate_sections`，刷新报告中的小节、修复预估及软门槛，并用与正常完成相同的写回过程更新审计 JSON、Markdown 审计段及已有 `text.md` 字段。缓存中的抽样模式与依据、逐页读数、统计、仲裁结果和阈值保持原值，不调用新的 OCR、不扩展审计页数，不靠 `--force` 或 `--full` 修复目录覆盖问题。报告中的来源及产物路径对应本次调用，新增小节从当前目录取得，不从旧报告猜配。

写回所需的公式区域数量继续属于既有零模型区域信息：优先复用当前 PDF 指纹一致的既有区域文件；缺失或不适用时沿用正常路径已有的无 OCR 区域提取及降级处理，不新增公式审计。缓存与正常路径共享写回行为，避免两处分别维护状态规则；写入失败沿用现有失败返回，不返回未落盘的成功状态。上游修正后交付固定提交，本仓仅更新该内核依赖及锁文件，不在消费者或本仓 `sync-audit` 中补造遗漏小节。CLI、报告字段类别、抽样继承规则和已完成的页号修正保持兼容。

因果、取舍和保护边界来自 P5 §11：
本次触发事实是原有分批章节场景的正式失败，不是新增业务要求。R5 已完成第 1 章，并在第 2 章维持累计映射、稳定 `book_id` 和去重导入；但上游缓存返回旧的小节集合，使第 2 章没有对应审计。错误状态由 `pdf-processing-core` 的报告生成和缓存返回拥有，应在其返回报告前同步当前小节；本仓继续消费上游报告并同步 metadata。

选择复用已审计逐页结果、重新生成当前小节报告。替代方案 `--force` 会重做 OCR，`--full` 会改变模式并可能读取更多页；两者都不能作为分批处理的常规补偿。由本仓猜配或直接修补报告会重复上游聚合和状态规则，且无法保持审计 JSON、Markdown 与正文一致，故不采用。

本次应保持：同一源 PDF 的识别缓存、原指纹/DPI 有效性、抽样解释和阈值、稳定身份、累计成果、导入去重、既有失败处理。应改变：当前新增的小节必须出现在复用缓存后的报告和相关字段中。若当前小节没有任何已读页，仍按原抽样继承规则表达；不能把明确存在的 `n/a` 读数改成可信。不会因为移动或新增小节而重新 OCR，也不删除原失败产物或清空知识库。

实施顺序为：内核负责人修正单文件缓存返回及共有写回 → 按既有实现审核确认直接影响 → 提交并由本仓固定新的内核提交 → 按有效测试步骤恢复受影响业务。当前原始失败已经说明 W01 不符合既定预期，继续采用同一业务检查，不新增样本、模型对照、采集设施或局部测试义务；具体恢复和已写入成果的处理由测试步骤负责人在正式复验前写清。

当前实现改动在 lib/pdfx/texlayer_audit.py：缓存命中和正常完成共用写回，返回的 report 与实际写入保持一致；已有 n/a 不能因空可疑页集合变为 trusted。报告、Markdown 与正文已有字段使用同一逐页事实，不新增评分标准。仅没有已读页的抽样章节继续原继承约定。写入失败沿原错误处理传播；区域测绘失败沿原非致命降级。没有历史缓存迁移、缓存删除或知识库清空。

### 2.3 同页目录次序

以下提取 P6 §12.1–12.2 的事实、方案与影响；引文“本仓”指下游，core 是上游：
固定内核 `38b853f1c086cb33ed2195b5a078b3cbb0495825` 的 `lib/pdfx/toc_llm.py:38–60` 要求按纸面阅读顺序返回标题、层级和印刷页码；`inject_toc.py:1106–1136` 按目录页顺序汇入条目。原 B 的纸面目录明确是第 1 章后接 1.1、第 2 章后接 2.1，两个章/节对分别同起于物理页 2、3。原样本和 R7 产物见下游 [failure-diagnosis.md](https://github.com/ScholarWorkflow/pdf-book-pipeline/blob/d329e408b28c21c085a78a9184ea26c8a980e7ba/plan/nix-full-workflow/failure-diagnosis.md) 与 [execution-results.md](https://github.com/ScholarWorkflow/pdf-book-pipeline/blob/d329e408b28c21c085a78a9184ea26c8a980e7ba/plan/nix-full-workflow/execution-results.md)。

同一内核 `inject_toc.py:1243–1251` 合并编号条目和成功附着条目时，按 `(physical, -level)` 排序。同页二级条目因而位于一级章前；`864–875` 再把首条强制整理为一级，`1278–1281` 将顺序和层级写回 PDF。本仓 `split_and_extract.py:157–187` 依书签顺序把更深条目挂在前面最近的较浅条目下，不按标题中的章号重猜归属。这条代码路径即使接收正确识别的条目，也会破坏同页父子关系。

条目关联有明确源码依据：`inject_toc.py:1163` 的编号集合保留 `all_entries` 中同一字典引用，`_attach_unnumbered` 在 `812、834–837、849–852` 原地写入定位并返回同一条目，`list(all_entries)` 只复制列表。合并前因此可以取得原条目次序，并保持两个筛选集合与原对象的一一对应，不需要标题匹配或新增序列化标识。

错误排序由上游目录注入程序拥有，修改在该原仓库完成；不修改消费者、夹具预期或下游树构建来补偿。R7 未保留识别原文及内部定位分支，仍不宣称本地复现能追回那次模型输出。`ensure_toc` 抽验警告的放行方式和诊断信息缺失、锚定回退中的旧定位问题不纳入本次产品修正。

#### 选定方案与影响（原 §12.2）

选定方案仅替换同一物理页内的排序依据：保持原物理页主排序，将原解析目录的阅读顺序作为同页次序。合并后的条目须仍关联其原条目，不按展示标题识别或合并。保留有页码条目和成功附着条目的原筛选结果；同页的无页码章标题也须保留原相对位置，不能被两个分类列表的拼接移到末尾。内部索引、对象引用或等价数据表达可由实现者选择，不增加公开字段或接口。

仅把 `-level` 改成 `level` 会把同页所有章排在所有节前，仍可能把前一章的小节挂到后一章，因此不采用。完全删除物理页排序会扩大不同页的行为变化，也不采用。向下游补按章号猜配规则会转移上游职责，并无法覆盖不含编号的目录，不采用。

本次改变的是同页写回顺序；保留原识别结果中的标题、层级及页码，保留物理页主排序、编号定位、无页码附着、原筛选数量、抽验阈值、锚定回退、结构数量检查、层级合法化和备份写回。数据格式、CLI、失败返回、身份和知识库流程不变；不迁移历史文件、不覆盖 R7 错误产物、不改视觉服务或 Nix 权限配置。

静态反例限定于该决定的直接影响：章与小节同页时应保持章在前；多个章/节对共用一页时应各自维持原相邻顺序；成功附着的无页码条目不因分类合并被移位；标题相同不合并为同一条目。不同物理页仍按原页码主序排列。这些检查用于确认方案，没有授权新增样本矩阵或逐过程取证。
